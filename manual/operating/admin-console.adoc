=== Administration consoles

The engine starts independently of mudlibs. Its player port presents a public
directory of direct connection details; its TLS admin port manages mudlib lifecycles and engine-owned administrator
grant records. Each mudlib runs in a separate worker JVM with its own player/admin
port pair. Mudlib administration operates on that worker's live objects.

[[engine-owner-and-administrator]]
==== Owner and administrator access

The *owner* of an engine instance is the operating-system account that owns its
private state directory, normally the account that starts it. Owner access grants
full engine authority through a Unix-domain socket on the host. Run the console
as that account, directly or through SSH. This does not require Unix root or
`sudo`; ownership is not a grant in the administrator registry.

An *administrator* is a named JVMud identity with an access token and explicit
grants. Administrators connect over TCP/TLS. An `engine` grant includes all
mudlibs and administrator management; `mudlib:<id>` is limited to one mudlib.
These identities are separate from OS accounts and player accounts.

[cols="2,2,3",options="header"]
|===
|Invocation |Transport |Authentication and authority
|`jvmud-console --owner` |Default engine's Unix socket |OS owner; full engine authority
|`jvmud-console --socket <path>` |Specified Unix socket |Same owner authentication
|`jvmud-console` |TCP/TLS to `localhost:4001` |Fingerprint, administrator name and token; explicit grants
|`jvmud-console <server> [<port>]` |TCP/TLS; default port 4001 |Same administrator authentication
|===

`--owner` must stand alone. `--socket` requires a path. Neither uses a TCP port
or administrator credentials. Omitting flags uses TLS administrator access even
though the destination is localhost.

==== Bootstrap and connect

Bootstrap as the engine owner:

[source,shell]
----
scripts/jvmud-start
# In another terminal:
scripts/jvmud-console --owner
----

[source,text]
----
admin-create operator
grant operator engine
available
start smallmercies 4100 4101
status
----

`--owner` uses `~/.jvmud/engine-4000/engine.sock` and authenticates through your
OS account. For custom engine state, use `--socket <state-directory>/engine.sock`.

Store the issued random token securely; it is displayed only once. The engine
stores its hash and grants. Remote connections require the certificate fingerprint
printed by the engine, obtained through a trusted channel:

[source,shell]
----
scripts/jvmud-console                     # localhost:4001
scripts/jvmud-console server.example      # server.example:4001
scripts/jvmud-console server.example 4401 # server.example:4401
----

The console prompts for the trusted certificate fingerprint, administrator name,
and token. Token input is hidden. These values are not saved between connections.
Supply `--user`, `--fingerprint`, and `--token-file <private-file>` when no
interactive terminal is available. Explicit `--host` and `--port` options remain
supported. Local TCP connections use the same TLS authentication; the Unix socket
provides initial bootstrap and recovery. Engine grants include all mudlibs;
`grant <name> mudlib:<id>` limits an administrator to one mudlib. Grants are
independent of OS accounts, player accounts and in-game wizard privileges.

`available` lists names under the engine's configured mudlib directory.
`start <name>` resolves `<mudlib-dir>/<name>/jvmud/<name>.config` and defaults to
player/admin ports 4100/4101. Occupied ports return an error. Supply another pair
for additional mudlibs, or `0 0` for OS-allocated ports. Engine ports still default
to 4000/4001.
The host operator selects `--mudlib-dir` at startup; it defaults to `mudlibs`
under the launch root. Both local and networked administration reject host
paths, traversal, and escaping symlinks. Restarts revalidate the same boundary.

Connect to a mudlib's admin port for `objects`, `inspect`, `call`, `reload`, and
other mudlib commands. `quit` disconnects only the console. `stop` and `restart`
are engine commands; `shutdown` stops the engine and all workers. A worker crash
closes its connections while leaving the engine and other mudlibs running.

The private engine state defaults to `~/.jvmud/engine-<player-port>` and contains
its recovery socket, registry, TLS identity and bounded worker logs. Override it
with `--state-dir`. Keep it outside mudlib trees. Workers launch directly with
Java and retain the host account's OS permissions. Separate JVMs contain worker
crashes; they are not a security boundary against hostile code. No external
sandbox package is required.

See the repository's `docs/ENGINE-ADMINISTRATION.md` for isolation limits, timeout
behavior, certificate management and the complete operating workflow.
