[[_admin_cli]]
=== Live Admin CLI

Start a server with an explicit, separate administration port:

[source,shell]
----
scripts/jvmud-start --port 4000 --admin-port 4100 mudlibs/smallmercies/jvmud/smallmercies.config
----

Connect from another terminal as the same OS user:

[source,shell]
----
scripts/jvmud-cli --port 4100
----

The CLI displays the selected server's admin port and world path. Commands act on
the selected mudlib, sharing its actual objects and execution queue with
player input and ticks. No new world is booted. Mounted worlds are not selected
by this interface. Every input line is an admin command, not a player command.

[source,text]
----
help
pwd
ls /
cat /room/square.c
objects
inspect room/square
call room/square short
quit
----

`/` is the manifest-selected mudlib source root. `objects` refreshes the live
registry, including connected player objects. `quit` or terminal EOF disconnects
only this client. The attached CLI rejects `boot`; select another server by
connecting to its admin port. Stop the server in its own terminal with Ctrl+C.

Administration is opt-in and always binds `127.0.0.1`, even when player Telnet
binds all network interfaces. A random credential is created with owner-only
permissions at `~/.jvmud/admin/<admin-port>.token`. The client reads it automatically;
normal server shutdown removes it. A stale credential after a crash requires
explicit removal after confirming that the old server has stopped.

Override the credential path with `--admin-token-file <path>` on the server and
`--token-file <path>` on the CLI. Startup never overwrites an existing credential.
Use a different player/admin port pair for every independently running server.

To investigate a changed object, edit its LPC source, run `reload <path>`, and
inspect the result. `clone <path>` creates an instance; `destruct <handle>` removes
one. These commands affect live state. Reload does not migrate all state or
references; verify callers and avoid assuming occupied rooms or players can be
replaced transparently. Long administrative commands can delay player input and
ticks because commands execute under the world's lock.

The complete command syntax is in <<_commands>>. Compilation diagnostics use the
running server's configured observer; the attached client does not replace it.
