=== Command Routing

Input passes from the Telnet session to the hosted instance and the profile's
LPC command behavior. The configured `transport.control_prefix` reserves an
escaped namespace for connection controls; its default is `//`.

* `//help` and `//quit` are transport controls in profiles using the default transport prefix.
* `look` and movement verbs go to the mudlib after login.
* Ordinary single-slash commands remain available to mudlib code.
* `load`, `inspect`, and `reload` run through the authenticated admin connection
  against the selected live mudlib. They are not player Telnet commands.

If a command is unrecognized, first identify which of these contexts received it.
Then check the active profile's lifecycle mappings and command registration.

To trace gameplay input in Java, start with `MudlibRuntime.refreshCommandActions`
and `dispatchCommand`. The package-private `engine.instance.lpc.LPCCommands`
owns the actor's action table, command aliases, active verb, failure text, and
dispatch order. `MudlibRuntimeContext` delegates LPC command operations to that
owner. `LPCWorldInteractions` coordinates movement, nearby lifecycle callbacks,
and explicit refresh traversal; `MudlibRuntime` retains its selected refresh hook
and runtime binding. The mudlib supplies the action methods and decides which
commands it accepts.
