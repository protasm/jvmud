=== Instance And Transport Internals

`MudlibBoot` reads profile metadata, assembles runtime configuration, and loads
startup content. `MudInstance` coordinates the running world, LPC objects,
Personas, lifecycle dispatch, and scheduled work. `MudlibRouter` coordinates
explicitly mounted worlds. `TelnetServer` owns the listener and connection path.

Follow an input from transport to instance to LPC command handling when debugging
player behavior. Follow an efun from its catalog through runtime context and
instance services when debugging host effects. `compiler.runtime` is generated-code
support; `engine.world` owns the engine's world model.

The admin shell boots a separate runtime and is not a remote mutation channel.
Storage adapters live under `persistence`. Concurrency hardening and alignment
between LPC location bookkeeping and engine containment remain tracked in
`docs/DEFERRED_WORK.md`; avoid implying that package boundaries alone prove
production isolation.
