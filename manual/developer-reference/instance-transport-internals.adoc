=== Instance And Transport Internals

`engine.application.JVMud` starts engine endpoints independently of mudlibs and
supervises one separate worker JVM per mudlib. `MudlibWorker` boots through
`MudlibBoot` and reports readiness over private pipes. The engine then publishes
the mudlib's player/admin pair. `PlayerDirectory` displays connection details;
it does not enter a mudlib. A mudlib's `PlayerGateway` relays its direct player
connections, and worker-side `TelnetServer` handles that mudlib's Telnet sessions.
Quitting a mudlib closes the connection.

Each `MudInstance` owns a `MudlibExecution`: one thread serving its command queue
and clock. Player input, protocol callbacks, administration, and scheduled work
run serially there. Each manifest supplies its own `temporal_tick_interval`;
zero disables automatic ticks. Ticks use a delay after the preceding tick
completes, without accumulating catch-up ticks. No router-wide tick loop or
cross-world execution lock exists.

Telnet delivers input without interpreting LPC command results or generating
rejected-command messages. The mudlib owns that meaning and output.

Follow an input from transport to instance to LPC command handling when debugging
player behavior. `engine.instance.lpc.MudlibRuntime` owns hosted object execution;
`MudlibRuntimeContext` implements the language's generated-code context against
world, identity, scheduling, and storage services. Follow an efun from
`engine.instance.efun.EngineEfuns` to those services when debugging host effects.
`language.runtime` supports LPC values and generated code; `engine.model.world`
owns the world's containment graph.

==== Hosted LPC invocation

Invocation policy lives under `engine.instance.lpc`. `LPCInvocationStack` owns
canonical current/previous-object identities and restores call scopes after
normal returns and exceptions. Its execution-membership query also guards live
object reload. `LPCMethodInvoker` owns reflective selection, argument adaptation,
and invocation diagnostics. `MudlibRuntimeContext` delegates to those owners.
`LPCCommands` owns command actor, verb, failure text, and action registration
independently of the LPC object call stack.
Both invocation owners are package-private collaborators of the context. Target
loading and destroyed-object checks stay in the context, as do the absence and
failure rules for identifier and message-permission probes; those probes use the
invoker's prepared method-and-argument plans.

Required object calls prefer exact arity and can pad omitted trailing arguments
with LPC zero values. Optional calls also trim extra arguments and return LPC
zero for an absent method. Configured lifecycle hooks prefer the most-derived
declaring class before choosing arity, so an inherited exact match cannot bypass
a descendant's hook. Mudlib global functions use optional argument matching but
retain the caller's object context and fail if the method is absent. Keep these
entry points distinct when following a call through compatibility wrappers.

`LPCObjectLifecycle` remains the owner of selected receivers and reload state.
Ordinary calls and named-method callables follow the selected live revision;
inline closures retain captured code and share current fields with their
historical receiver. Nested same-object calls inside a historical closure stay
on that receiver until its scope ends.

==== LPC command dispatch

The package-private `engine.instance.lpc.LPCCommands` owns command actor scopes,
active verbs and failures, registration scopes, action tables, aliases, command
enablement, ordering, and dispatch. `MudlibRuntimeContext` delegates its existing
command API. The hosted runtime retains interaction refresh, and the context
coordinates movement, lifecycle, and sessions on the instance queue.

The command owner uses `LPCInvocationStack` for lexical handlers,
`LPCObjectLifecycle` for canonical actors and live receivers, and
`LPCMethodInvoker` for action method calls. A narrow host interface supplies
environment lookup, actor activity, private output, and the current ordering and
catch-all argument flags. Those policy flags are read from the host when needed.
Callers establish an actor scope before dispatch. Nested calls restore the outer
actor, verb, and failure state even after exceptions.

[%unbreakable]
--
Persistent actions survive interaction refresh while nearby lifecycle callbacks
rebuild scoped actions. Dispatch snapshots matching actions, retaining the
manifest's ordering and catch-all argument policy. An accepted action or actor
movement handles the command; otherwise the environment movement fallback runs
before failure text is written. Command enablement remains lifecycle metadata,
not a dispatch gate. Destruction removes actor and handler registrations; reload
keeps their stable object identity.
--

==== Scheduled LPC callbacks

The package-private `engine.instance.lpc.LPCScheduledCallbacks` owns authored
recurring and deferred registrations, task identities, cancellation, delivery,
and failure policy. `engine.model.time.WorldScheduler` owns deterministic time
and generic queued work; callbacks run when callers advance it, without a
background thread. The hosted instance advances time on its execution queue.
`MudlibRuntimeContext` delegates scheduling and coordinates destruction cleanup.
Its narrow host seam supplies the current tick method, live-registration checks,
runtime binding, and timed-error reporting. The context retains its public
`TimedRuntimeErrorHandler` and setter; the bridge uses the currently installed
reporter after lexical object and captured-actor scopes unwind.

Deferred registrations retain separate identities, argument arrays, and captured
actors even when they share a method name. Cancellation selects the earliest
pending match, breaking due-tick ties by registration order. Delivery consumes
the registration before checking the live target and compatible method. Captured
actors use `LPCCommands` scopes; null captures leave any ambient actor unchanged.
Recurring registration replaces the previous task. Missing tick methods skip an
occurrence without cancelling it. Recurring failures cancel before reporting;
deferred failures consume only their own registration. Runtime bindings restore
after both successful and failed invocation and error reporting. Target and
method preflight checks run outside the runtime binding.

`LPCInvocationStack` supplies the lexical target identity, `LPCMethodInvoker`
performs live named-method dispatch, and `LPCObjectLifecycle` owns the selected
receiver. Changing the selected scheduler does not migrate existing tasks.

==== Administration and storage

`communication.console.AdminConsole` connects to an engine or mudlib administration
endpoint. The engine owns TLS authentication and grants. Engine commands execute
in `EngineAdminCommandSession`; mudlib commands cross private worker pipes and
execute in `MudlibAdminCommandSession` on the instance's execution queue. No
administrator credentials are sent to worker JVMs. Direct player listeners relay
bytes to their worker, where Telnet negotiation, login, and commands are handled.

Storage adapters live under `storage`; engine administrator identities are
separate from mudlib player accounts. Manifest files are interpreted under
`engine.configuration`, outside the world model. See
`docs/ENGINE-ADMINISTRATION.md` for supervision and platform limitations.
