=== Compiler Pipeline

The compiler turns LPC source into JVM classes. The engine owns live world
state and supplies host services. The mudlib supplies authored behavior and
compatibility policy. The compiler can be used without starting a game.

The pipeline is deliberately staged so each step has a small job and a clear
artifact:

[cols="1,2,2", options="header"]
|===
| Stage | Input | Output
| Preprocess | LPC text, include resolution, and macro definitions
| Expanded source with mappings to original files
| Scan | Preprocessed source | A token stream
| Transform | Tokens and explicitly selected compatibility settings
| Normalized tokens, preserving original source
| Parse | Tokens | An abstract syntax tree for one LPC object
| Transform declarations | AST and selected declaration overrides
| Explicit declarations for semantic analysis
| Analyze | AST, inherited metadata, and callable signatures
| A semantic model with resolved names and types
| Lower | Semantic model | Typed intermediate representation
| Compile | Typed IR | JVM bytecode
|===

All stages live under `io.github.protasm.jvmud.language.compiler`.
`preprocessor`, `scanner`, `token`, `parser`, `type`, `semantic`, `ir`, and
`bytecode` name their responsibilities directly. `pipeline` coordinates them
and reports `CompilationProblem` values. `transpiler` applies the compatibility
transformations selected for a profile; it preserves upstream source files.

Compilation uses language-owned source resolution, settings, and callable
signatures. Runtime implementations of efuns are separate from the signatures
used for analysis. `language.efun` defines that callable contract and supplies
language-only built-ins through `LanguageEfuns`. The engine's
`instance.efun.EngineEfuns` composes those functions with JVMud's host operations.

After compilation, `language.execution` supplies class-loading and invocation
contracts. `language.runtime` contains the generated-code context contract and
LPC value operations: truthiness, coercions, indexing, strings, arrays, and
runtime type descriptors. These packages do not construct world or storage
services. `engine.instance.lpc.MudlibRuntime` hosts the authored objects, using
`MudlibRuntimeContext` to connect their requests to engine services.
The hosted context delegates current/previous-object scopes to
`LPCInvocationStack` and method selection, argument adaptation, and call
diagnostics to `LPCMethodInvoker`. Those hosted invocation policies remain under
`engine.instance.lpc`, separate from compiler analysis and the neutral runtime
contract.

The world model lives under `engine.model.world`, identity records under
`engine.model.identity`, scheduling under `engine.model.time`, and lifecycle
contracts under `engine.model.mudlib`. Manifest parsing and policy belong to
`engine.configuration`.
