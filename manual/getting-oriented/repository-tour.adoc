=== Core packages and repository tour

[[_repository_tour]]
All Java package names below begin with `io.github.protasm.jvmud`. The four
families organize responsibilities within one Maven artifact.

[cols="1,3",options="header"]
|===
|Package |Responsibility and starting points
|`language` |LPC semantics and reusable language facilities. `compiler` contains
`JVMudCompiler`, the staged `pipeline`, source resolution, and compatibility
transformations. `execution` contains compiled-class and object-handle contracts;
`runtime` supplies generated-code context and value operations. `efun` defines
callable signatures and language-only built-ins through `LanguageEfuns`;
`formatter` formats LPC source.
|`engine` |`application` owns startup, worker supervision, and updates;
`model` defines worlds, identities, time, and mudlib lifecycle contracts;
`configuration` reads and assembles manifest policy; `instance` runs one mudlib.
Its `lpc.MudlibRuntime` loads authored behavior; `lpc.LPCObjectLifecycle` keeps
live object identity and state separate from that behavior's program revision.
`lpc.MudlibRuntimeContext` adapts execution to world, session, and storage services.
`lpc.LPCInvocationStack` owns current/previous-object identity and call scopes;
`lpc.LPCMethodInvoker` selects methods, adapts arguments, and reports call failures.
`lpc.LPCWorldInteractions` owns authored movement, nearby interaction, perception,
and world metadata through `model.world.MudlibWorldProjection`; `WorldRuntime`
remains the authoritative containment graph.
`lpc.LPCCommands` owns command context, action registration, and dispatch.
`lpc.LPCScheduledCallbacks` owns recurring and deferred LPC callbacks;
`model.time.WorldScheduler` owns deterministic time and generic queued work.
`instance.session.InstanceSessions` owns connection and attachment transitions;
`InstanceSession` represents a connection before and after login, and
`PersonaAttachment` relates its selected Persona, Entity, and authored behavior.
Managed login policies and prompt flows live under `instance.session.login`.
`instance.efun.EngineEfuns` composes the language catalog with capability-filtered
object, world, session, command, scheduling, file, database, and host catalogs.
`diagnostics` checks a selected mudlib's preload manifest.
|`communication` |`transport` owns connection mechanics, `admin` interprets
administrative commands, and `console` supplies the terminal client.
`protocol` and `output` handle structured messages and text presentation.
|`storage` |Durable adapters under `filesystem`, `jdbc`, and `admin`.
|===

Choose a package by the responsibility it owns. A language operation should be
understandable without booting a game or opening a database. Engine instances
supply the world and host services that authored LPC requests. The model defines
world rules; the configuration reader interprets manifests; storage adapters own
durable formats. Communication delivers input and output while mudlibs interpret
player commands. These boundaries are part of source readability, not just a
filing convention.

`src/main/java/` contains these packages; `src/test/java/` mirrors their ownership.
Each mudlib manifest selects its LPC source root. Small Mercies keeps authored
content under `mudlibs/smallmercies/source/`; LP245 retains upstream `obj/`,
`room/`, and other content directly under `mudlibs/lp245/`. Their `jvmud/`
directories contain manifests and JVMud-owned adapters. Inspect the selected
manifest before assuming a source or storage layout.

`manual/` contains editable AsciiDoc; `docs/` contains the site, generated manual,
and API. Shared tools live in `scripts/`. `pom.xml` defines dependencies and
build profiles. See <<_documentation_generation>> before editing generated pages.

==== Java API migration

The preview Java packages and embedding API have intentionally changed to make
ownership explicit. Java integrations must update imports and construction code;
there are no compatibility alias packages. Names below are relative to
`io.github.protasm.jvmud`.

[cols="1,2",options="header"]
|===
|Previous name |Current owner
|`execution.*` |`engine.*`
|Compiler stage packages
|`language.compiler.<stage>`: `parser`, `pipeline`, `semantic`, `ir`, `bytecode`,
`scanner`, `token`, and `transpiler`
|`preproc`, `sourcepos`, and parser types
|`language.compiler.preprocessor`, `language.compiler.source`, and
`language.compiler.type`
|Neutral execution APIs
|`language.exec` becomes `language.execution`; `LPCRuntimeConfig` becomes
`LPCExecutionOptions`
|`LPCRuntime` +
Former package: `language.exec`
|`MudlibRuntime` in `engine.instance.lpc` owns hosted LPC objects and engine integration
|`RuntimeContext` +
Hosted state and services
|`MudlibRuntimeContext` in `engine.instance.lpc` adapts authored calls to hosted
owners, including `InstanceSessions`. `language.runtime.RuntimeContext` defines
the neutral generated-code contract.
|`InstancePersona` +
Former package: `engine.instance`
|`InstanceSession` in `engine.instance.session` represents the connection lifetime;
`PersonaAttachment` explicitly represents its selected Persona and Entity.
|`CoreEfuns` +
Former combined built-in catalog
|`EngineEfuns` in `engine.instance.efun` composes language-only built-ins and
engine-service adapters. `LanguageEfuns` under `language.efun` provides the
standalone language catalog.
|Mudlib boundary declaration and reader
|`MudlibConfiguration` and `MudlibConfigurationReader` in `engine.configuration`
|`JVMudCompiler` +
Former package: `language`
|`language.compiler.JVMudCompiler`
|===

The former source packages were `language.preproc`, `language.sourcepos`, and
`language.parser.type`. The former built-in catalog was
`language.efun.builtin.CoreEfuns`. The declaration and reader were
`MudlibBoundary` and `MudlibBoundaryConfigReader` in `execution.model.mudlib`.

On `InstanceHost`, replace `attachPersona(...)` and `detachPersona(...)` with
`attachSession(...)` and `detachSession(...)`, using `InstanceSession` as the
connection handle. Replace `isAttached(InstancePersona)` with
`isOpen(InstanceSession)` when checking connection lifetime. An open session can
still be awaiting login; use `session.attachment().isPresent()` when the caller
requires an attached Persona. Obtain the selected Persona through that attachment
rather than treating login as an LPC actor.

On the hosted runtime, replace `mudlibBoundary()` with `configuration()` and
`registerMudlibBoundary(...)` with `configureMudlib(...)`. The hosted context's
former `setMudlibBoundary(...)` is also `configureMudlib(...)`. Boot metadata
exposes its selected policy through `MudlibBootResult.configuration()`.

Use the compiler's `LPCCompilerContext` for compilation inputs. Code that needs a
world, sessions, or storage must assemble the engine's `MudlibRuntime` explicitly;
the language contracts do not create an engine implicitly. The existing
`scripts/jvmud-start`, `scripts/jvmud-console`, and `scripts/jvmud-format` names
remain the entry points for their respective tools. Direct Java invocations of
the compiler must use its new fully qualified class name above.
