Core packages

Find the owner of a behavior before opening a class reference.

One Maven project, six core package families

These are responsibility boundaries within one Java artifact, not independently versioned modules. All names begin with io.github.protasm.jvmud.

engine · World rules and identity

world, identity, time, mudlib, output, support.

Start with WorldRuntime, Place, Entity, Link, Player, Session, Persona, WorldScheduler, MudlibBoundary.

Read the engine package API →

compiler · LPC source to executable objects

preproc → scanner → parser → semantic → ir → bytecode; exec loads objects; runtime supports generated code.

Start with JVMudCompiler, CompilationPipeline, LPCRuntime.

Read the compiler package API →

instance · A running hosted world

Manifest boot, preloads, Persona attachment, lifecycle dispatch, mounted-world routing.

Start with MudlibBoot, MudInstance, MudlibRouter.

Read the instance package API →

transport · Player connections

Telnet framing, line input, echo negotiation, GMCP, and connection lifecycle.

Start with TelnetServer.

Read the transport package API →

persistence · Durable storage adapters

filesystem and jdbc; selected profiles own storage policy.

Start with FilesystemAccountStore and JDBC adapters.

Read the persistence package API →

cli · Live administration CLI

Virtual filesystem, compiler stages, object loading, inspection, invocation, and mutation.

Start with AdminClient and AdminCli.

Read the cli package API →

Choose the right layer

A world rule belongs in the engine; a hosted lifecycle belongs in the instance; a protocol mechanic belongs in transport. Generated-bytecode helpers belong in compiler.runtime. Authored game behavior and compatibility policy belong in the mudlib.
